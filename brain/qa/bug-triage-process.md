# Bug Triage Process

## Severity Levels

### Critical (P0)
- **Definition:** App crash, data loss, security breach
- **SLA:** Fix immediately
- **Priority:** Immediate

### High (P1)
- **Definition:** Major feature broken, significant UX issue
- **SLA:** Fix within 24 hours
- **Priority:** High

### Medium (P2)
- **Definition:** Minor feature issue, workaround available
- **SLA:** Fix within 1 week
- **Priority:** Medium

### Low (P3)
- **Definition:** Cosmetic issue, edge case
- **SLA:** Fix in next release
- **Priority:** Low

## Bug Lifecycle
1. **Reported** → Bug found and logged
2. **Triage** → Severity assigned
3. **Assigned** → Developer assigned
4. **In Progress** → Developer working
5. **Testing** → QA verifying fix
6. **Resolved** → Bug fixed and verified
7. **Closed** → Approved and closed
